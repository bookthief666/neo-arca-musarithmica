# M1.2.1 — Spatial Comprehension / Operative Continuity

**Repository:** `bookthief666/neo-arca-musarithmica`  
**Design branch:** `feature/m1.2.1-spatial-comprehension`  
**Starting authority:** `7dc5e3c66e4602478d4f8a23f45f136db457f0e1`  
**Parent milestone:** M1.2 — Spatial Arca Prototype  
**Date:** 2026-09-15

## 1. Purpose

M1.2 proved the core spatial thesis: the Arca can exist as a genuine R3F/Three.js object with real volume, a hinged lid, a physical interior, removable virgae, an extending carriage, constrained rod motion, a transverse reader, Tone II, and a revelation folio.

Owner Fold QA showed that this is a strong technical foundation but not yet an intelligible instrument. The object is visibly three-dimensional, but a first-time user still has to infer too much about what to touch, what changed, where a virga went, why the carriage moved, what a band is, when Tone II becomes relevant, and how LECTIO produces the four-voice result.

M1.2.1 therefore targets **spatial comprehension and operative continuity**, not visual polish and not WebXR.

The milestone succeeds when the machine itself explains its causal chain through geometry, constrained motion, restrained emphasis, and short diegetic guidance.

### Primary acceptance sentence

> Without opening Instrument Controls, a first-time sighted user on the Samsung Galaxy Z Fold 6 can understand where the virgae come from, where they go, how they are aligned, why Tone II becomes available, how LECTIO is performed, and where the resulting four voices came from.

### Architectural acceptance sentence

> Every physical action still resolves to the existing canonical instrument reducer; M1.2.1 must not introduce a second spatial state machine or new musical authority.

## 3. Existing implementation facts that shape this design

### 3.1 The reducer already contains the correct two-stage rod model

The canonical reducer already supports:

1. `RETRIEVE_ROD`
   - creates one rod instance;
   - sets `location: 'hand'`;
   - sets `heldRodId`;
   - enters `rod_retrieval`.

2. `PLACE_HELD_ROD`
   - preserves the same instance;
   - changes `location` to `workspace`;
   - clears `heldRodId`;
   - returns to alignment logic.

The current M1.2 spatial renderer bypasses that model by dispatching `DEPLOY_ROD` directly from storage to workspace. M1.2.1 must stop doing that for the primary spatial flow and instead express the reducer's existing `stored → held → seated` grammar.

`DEPLOY_ROD` may remain for legacy/direct-access compatibility where required, but it is not the primary M1.2.1 spatial interaction.

### 3.2 Object identity is already spatially sound

`Virgae.tsx` renders each carrier as one persistent 3D group across its lifetime rather than destroying one mesh and creating another. That property must be preserved.

M1.2.1 maps the three canonical conditions to physical poses:

```text
rod absent from state.rods
    = stored in Cell IV

rod.location === 'hand'
    = visibly retrieved / held transfer pose

rod.location === 'workspace'
    = seated in the carriage
```

The same visible object must travel from socket to held pose to channel.

The held/interpolation pose is presentation state only. It may use refs or animation values, but no new field may be added to `InstrumentState` for spatial animation.

### 3.3 Cell IV already has a real cavity but weak physical grammar

The current interior has cavity depth, persistent slots, and an operative clickable surface, but no strong physical cover/lid action. M1.2.1 must make Cell IV unmistakably read as a container that opens to reveal three removable virgae.

### 3.4 The camera currently follows semantic views too aggressively

The camera director currently has authored framings for `arca`, `cabinet`, `cell`, `working`, `tone`, and `revelation`, and a view change reclaims camera control.

M1.2.1 must separate **semantic instrument view** from **camera intervention**. Instrument state may change without the camera taking control away.

### 3.5 The accessible control layer is architecturally correct

`AccessibleInstrumentControls` owns no musical state and dispatches canonical actions. It must remain. Its sequence must be updated to mirror the same retrieve → place → align story as the spatial instrument.

## 4. Chosen interaction architecture

### 4.1 Canonical flow

The primary spatial path becomes:

```text
CLASP / LID
  ↓
OPEN_ARCA
  ↓
BANK I
  ↓
CELL IV visibly opens
  ↓
select stored virga
  ↓
RETRIEVE_ROD
  ↓
same virga rises from its mortise and remains visibly held
  ↓
carriage extends and one destination channel wakes
  ↓
select held virga OR active destination channel
  ↓
PLACE_HELD_ROD
  ↓
same virga seats in the channel
  ↓
repeat ×3
  ↓
slide/snap rods through canonical bands
  ↓
transverse aperture becomes continuous at canonical alignment
  ↓
Tone II selector becomes available
  ↓
ENGAGE_TONE
  ↓
LECTIO becomes available
  ↓
EXECUTE
  ↓
folio physically emerges
```

No new canonical instrument phase is required for this milestone.

### 4.2 Why this approach

This design gives the user a causal pause between retrieval and placement while using state the reducer already knows how to represent. It is more legible on touch than free six-degree-of-freedom drag-and-drop and more honest than slowing down a one-step `DEPLOY_ROD` teleport.

### 4.3 Explicitly rejected alternatives

**Direct auto-deploy with longer animation** is rejected as the primary flow because the canonical placement has already happened before the user understands it.

**Free 3D grab-and-drop** is deferred because it would add gesture ambiguity, hit-testing complexity, snap/rejection behavior, and mobile camera conflicts before the machine's basic grammar is learned. It remains a future XR-oriented evolution.

## 5. Cell IV physical grammar

Cell IV must become a real, legible subassembly rather than a thin clickable region.

### 5.1 Closed / unfocused state

Use one specific mechanism for M1.2.1: a **shallow sliding cover plate** over Cell IV that translates rearward beneath the bank rail when opened.

The cover must include:

- a clear perimeter seam;
- a small front finger lip or pull tab;
- restrained engraved identification: `CELLVLA IV · PINAX IV`;
- wood/brass construction consistent with the Historica cabinet;
- a generous invisible interaction volume on Fold.

Do not substitute a hinged flap, modal overlay, or alternate cover design during this milestone unless browser inspection proves the sliding plate physically impossible with the existing geometry. If that happens, document the collision and use the smallest geometric correction necessary rather than redesigning the whole interior.

### 5.2 Focused / open state

When `focusedCell === 4`:

- the cover translates rearward beneath the bank rail;
- the dark cavity becomes obvious;
- all three virga heads/finials are readable as stored objects;
- three sockets/mortises remain visible;
- empty mortises remain after retrieval.

No large modal overlay or separate panel may substitute for this physical reveal.

## 6. Virga retrieval and placement

### 6.1 Retrieval

Selecting a stored virga dispatches `RETRIEVE_ROD`.

The corresponding physical object must:

- rise approximately 15–25 mm above its mortise;
- shift slightly forward if needed to separate it from neighboring rods;
- remain visibly suspended in a stable held pose;
- retain its exact identity;
- leave the source socket visibly empty;
- not immediately jump to the carriage.

The exact offsets are presentation values and may be tuned through browser iteration, but they must remain human-scale in the existing 1 unit = 1 metre world convention.

### 6.2 Held state

While `heldRodId` is set:

- only the held virga receives restrained active emphasis;
- the other stored virgae remain inert except for normal hover affordance;
- the target carriage channel becomes uniquely emphasized;
- the user can still understand both source and destination in the same spatial scene;
- the camera must not cut away simply because the phase became `rod_retrieval`.

Suggested guidance:

> Seat the lifted virga in the illuminated channel.

### 6.3 Carriage extension timing

The carriage begins extending when the first rod enters the held state, not only after it is already seated.

This makes the machine reveal the destination before placement and gives the transfer a visible source → destination relationship.

The carriage remains extended once rod work has begun.

### 6.4 Placement

Placement can be triggered by either:

- selecting the held virga again; or
- selecting its uniquely highlighted destination channel / receiver.

Both interactions dispatch the same canonical `PLACE_HELD_ROD` action.

The same visible virga then follows a guided, physically legible path into its channel and settles to the canonical workspace pose.

The transfer path communicates lift → translate → seat. Avoid fades, disappearance, teleportation, or duplicated meshes.

### 6.5 Repetition

After a rod is seated, the next stored virga becomes the natural available retrieval target. The same grammar repeats for all required rods without adding tutorial chrome.

## 7. Working carriage and band comprehension

### 7.1 Carriage remains physically attached

The carriage must continue to read as a drawer/tray on runners coming from the cabinet. It must not feel like a separate floating workbench.

### 7.2 Channel identity

Each channel receives a subtle permanent Roman numeral marker `I`, `II`, or `III` engraved at its mouth. Avoid large modern UI labels.

The destination cue for a held rod must be unambiguous: only the correct receiver wakes.

### 7.3 Detents and indexed bands

The user needs to understand what a band is before being told to align one.

Use **Roman numerals `I–X`** as the canonical visible detent index along each working channel for this milestone. The first canonical read band therefore reads `I`.

The current position has a small mechanical/brass index marker adjacent to the relevant numeral.

Rod movement remains constrained along one axis. Continuous pointer travel maps to canonical integer offsets through the existing snapping geometry. No fractional musical state is introduced.

Suggested guidance while not aligned:

> Slide each virga until band I lies beneath the reader.

## 8. Transverse reader

The current conceptual mechanism is retained: two brass rails form a transverse bridge with a reading aperture one band wide, and per-channel shutters express whether the currently presented material is readable.

M1.2.1 should improve the hierarchy so that the reader clearly appears to **read through** the virgae rather than cover them.

### Required states

- no rod in a channel → aperture visibly unresolved / empty;
- rod present on an untranscribed band → channel shutter visibly blocks the aperture;
- rod present on a verified band → aperture remains open;
- all required rods on the canonical verified band → one continuous opening spans all three channels.

The primary success signal must remain geometric and understandable in greyscale and reduced motion. Warm illumination or a medallion highlight may confirm success but must not be the sole cue.

---

## 9. Tone II mechanism

Tone II becomes a persistent **rotary brass selector** mounted at the lower-right of the Mensa/lid frame.

### 9.1 Persistent identity

The selector includes a fixed engraved `TONVS II` label and a small pointer/index. It exists in all open-instrument states.

### 9.2 Availability states

Before canonical alignment:

- visually dormant;
- physically present;
- interaction disabled.

When `isAlignmentReady(...)` becomes true:

- the selector subtly wakes through restrained material/emissive emphasis;
- guidance points from the now-concordant reader to Tone II;
- it becomes operable.

Suggested guidance:

> The rule is concordant. Engage Tone II.

### 9.3 Engaged state

On `ENGAGE_TONE`, the selector rotates approximately **35°** so its pointer seats against the engraved `II` index. Reduced-motion mode may snap rather than animate this rotation.

This mechanical state change is the authoritative visual indication that Tone II is engaged; do not substitute a generic press flash.

---

## 10. LECTIO mechanism

LECTIO is the final physical action before execution and must never appear from nowhere.

### 10.1 Persistent presence

Use a persistent **short brass lever on the front-right of the carriage**, accompanied by a small engraved `LECTIO` plate. It is present as soon as the carriage is visible.

Its touch hit volume may be larger than its visible hardware.

### 10.2 State progression

- rods incomplete / misaligned: present but mechanically locked/dormant;
- alignment ready but Tone II absent: still locked;
- Tone II engaged: visibly unlocks/wakes;
- execution ready: clearly operable;
- activation: lever rotates forward/down approximately 20–30° while execution begins;
- success: returns to a readable resting/used state while the folio emerges;
- error: returns to a restrained fault/retry presentation without losing the rod disposition.

Suggested guidance once available:

> Tone II is set. Operate LECTIO.

The current behavior of conditionally creating a small reading cylinder only when execution is ready must be replaced by this persistent spatial identity.

## 11. Revelation continuity

Execution success preserves the machine that caused it.

The rods, transverse reader, and carriage remain present. The revelation folio emerges mechanically from the instrument, preferably from a slot beneath or behind the reading mechanism, so the causal chain remains visually legible:

```text
virgae
  ↓
transverse reader
  ↓
LECTIO
  ↓
folio
```

Do not replace the instrument with a result screen.

A gentle camera widening/tilt may include the folio and carriage together.

The folio must continue to avoid unsupported staff notation, octave, register, or modern rhythmic semantics.

## 12. Camera ownership model

M1.2.1 separates semantic state from camera choreography.

### 12.1 Major topology events that may reframe

Only these events deliberately take limited camera authority:

1. closed → open instrument;
2. **first** successful placement into the working carriage, detected presentation-side by the workspace-rod count transition `0 → 1`;
3. execution success / revelation.

The `0 → 1` detection belongs to presentation refs/derived values and must not add canonical state.

The reframe is gentle and preserves spatial orientation.

### 12.2 Minor operational events that must not recapture the camera

These normally preserve user orientation:

- focus Bank I;
- open Cell IV;
- retrieve a virga;
- place second/third virgae;
- drag rods among bands;
- achieve alignment;
- engage Tone II.

Presentation may adjust target slightly if required for visibility, but it must not feel like a cinematic cut.

### 12.3 User ownership

After the user manually orbits, the camera director yields until either:

- the user activates `Recentre the instrument`; or
- one of the three major topology events above occurs.

The existing recentre control remains available and discreet.

## 13. Guidance hierarchy

The machine teaches through three layers, in this order:

1. **Geometry** — a real cover, receiver, detent, selector, or lever suggests the operation.
2. **Restrained emphasis** — only the relevant mechanism wakes.
3. **Scholium** — one short concrete instruction if needed.

The Scholium must not substitute for missing physical affordances.

### M1.2.1 Historica guidance text

- `open_arca` — `Open the instrument.`
- `focus_bank_i` — `Open Bank I.`
- `open_cell_iv` — `Open Cell IV; the verified virgae are stored within.`
- `deploy_rods` — `Lift a virga from its socket.`
- `place_held_rod` — `Seat the lifted virga in the illuminated channel.`
- `align_rods` — `Slide each virga until band I lies beneath the reader.`
- `engage_tone_ii` — `The rule is concordant. Engage Tone II.`
- `read_transverse` — `Tone II is set. Operate LECTIO.`
- `await_execution` — `The Arca is reading.`
- `inspect_revelation` — `Four voices are disclosed.`
- `recover` — `The disposition is preserved; restore the reading.`

The affordance identifier `deploy_rods` remains unchanged for compatibility; only its spatial action/copy now means retrieval into the existing held state.

No tutorial-memory subsystem is introduced in this milestone. Quiet/expert guidance can be refined later.

## 14. Accessibility parity

The semantic control surface remains permanent and mirrors the physical grammar rather than bypassing it.

### Required accessible sequence

```text
Retrieve virga
→ held state announced
→ Place held virga
→ adjust band using slider semantics
→ Tone II
→ LECTIO
```

The accessible surface dispatches the same canonical actions as the scene.

Rod movement retains:

- `role="slider"` or an equally correct semantic control;
- `ArrowUp` / `ArrowDown` movement;
- `Home` / `End` endpoints;
- canonical integer offsets only;
- readable band-status text.

The **Instrument controls toggle** must always remain keyboard reachable. When the panel is expanded, every currently valid semantic action must be in normal tab order with appropriate disabled states. The panel may remain visually collapsed by default; hidden descendant controls are not required to remain focusable while collapsed.

## 15. Touch and hit-target rules

Samsung Galaxy Z Fold 6 touch remains first-class.

Visible historical hardware does not need to be visually enlarged merely to satisfy touch. Generous invisible or transparent interaction volumes may wrap:

- Cell IV sliding cover;
- virga finials;
- the currently valid destination channel;
- Tone II selector;
- LECTIO lever.

Hit volumes must track actual objects and avoid overlap between competing actions.

Gesture ownership remains explicit:

- touching/dragging a seated virga owns the gesture and prevents orbit;
- touching empty scene/cabinet exterior allows orbit;
- two-finger pinch handles dolly;
- a held-rod placement tap must not simultaneously orbit the camera.

Free six-DOF drag-and-drop is out of scope.

## 16. Error and recovery behavior

Execution failure preserves physical understanding.

On `EXECUTION_ERROR`:

- rods remain where they are;
- carriage remains extended;
- alignment disposition remains visible;
- no false result folio appears;
- the user is not transported to another screen;
- if `isExecutionReady(...)` remains true, LECTIO remains operable as the retry action and redispatches `EXECUTE`;
- if execution is no longer canonically ready, the spatial emphasis follows the actual next canonical affordance instead of inventing a reset path.

Suggested message:

> The reading was not accepted. The disposition has been preserved.

No global reset button is added merely for convenience. Closing the Arca remains the explicit full reset because `CLOSE_ARCA` already returns to initial canonical state.

## 17. Performance constraints

M1.2.1 is comprehension work, not a license to increase rendering cost substantially.

Preserve the M1.2 discipline:

- 1 world unit = 1 metre;
- bounded DPR;
- no physics engine;
- no large postprocessing stack;
- no giant external texture pack;
- no unnecessary shadow-casting lights;
- no per-frame React state for animation;
- no R3F architecture rewrite.

New geometry should be low-cost and mechanically meaningful.

Report the before/after render-cost probe and bundle sizes. Do not fabricate FPS. Physical Fold FPS must be measured only if the environment genuinely permits it.
