# M1.2.1 Spatial Comprehension / Operative Continuity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the M1.2 spatial Arca understandable on a Samsung Galaxy Z Fold 6 without opening Instrument Controls, while preserving the existing canonical reducer, verified historical authority, and future XR-ready object identity.

**Architecture:** Keep `InstrumentState` and `instrumentReducer` authoritative. Replace the spatial renderer's direct `DEPLOY_ROD` shortcut with the reducer's existing `RETRIEVE_ROD → location:'hand' → PLACE_HELD_ROD` path, and derive every new 3D pose, highlight, camera mode, and mechanism state from canonical state. Add only presentation helpers/components around Cell IV, held virgae, carriage receivers/detents, Tone II, LECTIO, and camera choreography; do not add a second spatial state machine.

**Tech Stack:** React 19, TypeScript 5.9, React Three Fiber 9, Three.js 0.180, Vite 7, Vitest 3, Testing Library, existing Python historical kernel/test suite.

**Spec:** `docs/superpowers/specs/2026-09-15-m1.2.1-spatial-comprehension-design.md`

## Global Constraints

- Implementation branch: `feature/m1.2.1-spatial-comprehension`.
- Required implementation starting HEAD before runtime changes: the branch HEAD containing the approved spec and this plan; it must descend from M1.2 authority `7dc5e3c66e4602478d4f8a23f45f136db457f0e1` without rewriting history.
- Preserve 1 Three.js unit = 1 metre.
- Preserve the M0.9 historical kernel, verified Vperm, verified Rperm03, Tone II printed-p.51 map, provenance, canonical read-band semantics, and symbolic execution semantics.
- Do not add octave, register, BPM, staff notation, hidden ficta, or modern beat semantics.
- Do not reopen Ghost/backend architecture.
- Do not implement WebXR, Quest controllers, hand tracking, free six-DOF dropping, physics, Neo-Arca, or Modus Haereticus.
- Keep `?renderer=legacy` and WebGL fallback behavior intact.
- Spatial presentation state must never be added to `InstrumentState`.
- Touch at 390×844 is first-class; desktop and 884×960 remain supported.
- Reduced motion may change animation timing only, never canonical state.
- Use TDD for behavior changes: failing test, verify failure, minimal implementation, verify pass, then commit.
- Run the real browser and inspect rendered pixels for every geometry/camera task; unit tests alone do not satisfy visual acceptance.

- [ ] **Step 2: Implement the minimal pure operative helpers**

Use canonical arrays only:

```ts
export function heldRod(state: InstrumentState): ColumnRodInstance | null {
  return state.heldRodId
    ? state.rods.find((rod) => rod.instance_id === state.heldRodId) ?? null
    : null
}

export function targetLane(manifest: HistoricalManifest, state: InstrumentState): -1 | 0 | 1 | null {
  const held = heldRod(state)
  if (!held) return null
  const index = manifest.rod_templates.findIndex((template) => template.template_id === held.template_id)
  return index >= 0 && index < 3 ? ((index - 1) as -1 | 0 | 1) : null
}

export function shouldExtendCarriage(state: InstrumentState): boolean {
  return Boolean(state.heldRodId || state.rods.some((rod) => rod.location === 'workspace'))
}

export function workspaceOffsets(
  manifest: HistoricalManifest,
  state: InstrumentState,
): [number | null, number | null, number | null] {
  return manifest.rod_templates.slice(0, 3).map((template) => {
    const rod = state.rods.find(
      (candidate) => candidate.template_id === template.template_id && candidate.location === 'workspace',
    )
    return rod?.vertical_offset ?? null
  }) as [number | null, number | null, number | null]
}
```
