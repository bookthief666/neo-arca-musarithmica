# Neo-Arca Musarithmica -- reproducible dependency lock
#
# requirements.txt states the ranges the project is designed against.
# This file pins every package actually resolved into a working venv --
# direct dependencies and their full transitive closure -- to the exact
# version tested. It is what "byte-identical MIDI reproduction" is scoped
# to: determinism.Provenance.runtime records python/music21/implementation
# per response, but the full closure here is what actually determines
# serialization behavior (fastapi/pydantic/starlette affect the API
# response shape; music21 alone affects MIDI byte layout).
#
# Regenerate after any requirements.txt change or dependency upgrade:
#   python -m venv .venv && source .venv/bin/activate
#   pip install -r requirements.txt
#   pip list --format=freeze > requirements.lock.txt
#
# Install from the lock for a reproducible environment:
#   pip install -r requirements.lock.txt
#
# WHAT THIS LOCK DOES AND DOES NOT PROVE
#
# Pinning every version, as this file does, is necessary for reproducible MIDI output
# but it is NOT sufficient on its own. A wheel built for a different operating system,
# CPU architecture, or Python build can differ in floating-point rounding, binary layout,
# or available optional acceleration even at an identical package==version pin -- pip
# resolves a version pin to whatever wheel matches the *installing* machine, not to one
# specific binary artifact. Byte-identical MIDI (docs/DETERMINISM.md, tier D) is only
# claimed for the environment this lock was actually generated and tested against, given
# below, not for "these versions on any machine".
#
# TESTED ENVIRONMENT (exact, not a range):
#   OS / kernel:     Linux 6.18.44-fc-v24 (x86_64)
#   platform string: Linux-6.18.44-fc-v24-x86_64-with-glibc2.39
#   architecture:    x86_64
#   Python:          3.11.15 (CPython), built 2026-03-03, GCC 13.3.0
#
# Reproducing this exact tier-D guarantee elsewhere means matching all four of the above,
# not only the package versions below. A different OS/arch/build is tier B territory at
# best (same music, not necessarily the same MIDI bytes) until it has actually been
# tested -- see docs/DETERMINISM.md for what tier B does and does not promise.
